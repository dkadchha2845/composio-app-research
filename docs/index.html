The agent: one protocol, run 100 times

The work is done by an LLM agent with web search and fetch tools. Every app goes through the same six steps. Verdicts come from rules in code, not from the model, so the same facts always get the same verdict.

Run it

git clone https://github.com/dkadchha2845/composio-app-research && cd composio-app-research
pip install anthropic composio
export ANTHROPIC_API_KEY=sk-...           # COMPOSIO_API_KEY for --backend composio
python agent/research_agent.py --dry-run          # plan, no network
python agent/research_agent.py --ids 1-100        # full run → data/runs/latest.jsonl
python agent/verify.py rules  data/final.json     # loop 1
python agent/verify.py score  data/verification.json
python agent/build_page.py                        # rebuilds this page

How this run was done: the dataset here was produced by this protocol with Claude as the agent runtime, using its web search and fetch tools. research_agent.py packages the same protocol to run headless (Anthropic server tools, or the Composio SDK for search and scrape).     Verification: accuracy went from 88–90% to 96% on apps the agent had not seen

    Accuracy is scored on three fields that decide the build plan: access gate, MCP status and verdict. Auth method matched the docs for 30 of 30 apps in both passes, so it isn't the hard part.

    Pass 1 used model knowledge only, recorded before any lookup. Pass 2 was grounded in vendor docs. The stratified sample was 30 apps (3 per category, seed 2026) and fed the fixes. The held-out sample was 10 untouched apps, scored on the final data. Scoring 100% on the stratified sample after fixing it would be circular, so it isn't reported.
